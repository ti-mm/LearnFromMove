# RL and gain compensation analysis

## Paired RL

Drag, Ten-Choice, and Rotation share the `latentguiworld-train` GRPO entry point.
The three configurations in `configs/` select the task family and its environment
loop. For each family, prepare the paired training and validation Parquet files
using `gui_agent_captcha.benchmarks.exploration_depth.six_env_rl_dataset`.
See [data preparation](training.md#data-preparation-modules).

```bash
latentguiworld-train --recipe drag_rl --model models/latentlearner-sft \
  --train-files data/training/drag/train.parquet \
  --val-files data/training/drag/validation.parquet --output runs/drag-rl
```

Use `ten_choice_rl` or `rotation_rl` with the corresponding data for the other
families. The three recipes retain the paper's 5,120 prompts, 16-prompt batches,
five rollouts per prompt, and learning rate of 1e-6. Evaluate selected SFT and RL
checkpoints with `latentguiworld-eval`; environment-specific success rates support
the paired-policy comparison.

## Pearson correlations

Collect egocentric Drag measurements while evaluating each checkpoint:

```bash
latentguiworld-eval --model models/latentlearner-sft --variant drag_egocentric \
  --gain-analysis --output results/sft-drag
latentguiworld-eval --model models/drag-rl --variant drag_egocentric \
  --gain-analysis --output results/rl-drag
latentguiworld-pearson --sft results/sft-drag/gain_movements.json \
  --rl results/rl-drag/gain_movements.json --output results/pearson.json
```

The same commands support vLLM through `--server-url` and `--served-model`.
The collector reads evaluator state while each local episode is available and
writes `gain_movements.json` containing episode IDs, success flags, and numeric
movement measurements. Temporary screenshots and episode traces are removed
when the evaluation context closes.

For each `move_to` producing nonzero held-object movement, the script computes
`alpha = dot(u, e) / dot(e, e)`, where `u` is the commanded displacement in screen
pixels and `e` is the pre-action target-minus-object residual. A zero residual
has no defined coefficient. It takes the median within each episode, then
computes Pearson correlations across episodes with `g` and `1/g`, giving each
episode equal weight. Success and failure episodes both contribute.

Two cohorts use the paper's definitions:

- **All held moves:** every movement with a defined coefficient.
- **Filtered:** visible target, residual of at least 20 pixels, ideal correction
  within the action-coordinate range, and no clamping. Episode medians are
  recomputed after filtering.

The output includes both correlations for both cohorts, low/high-gain median
coefficients, coverage counts, and comparisons on shared movement episode IDs.
Low gain means `g < 1`; high gain means `g > 1`. Fewer than two episodes or a
constant correlation variable produces JSON `null`. Episodes without computable
movement remain in success-rate counts and are listed separately.

`gain_movements.json` has two arrays: `episodes` with `pair_id` and `success`, and
`movements` with `pair_id`, `frame`, `gain`, `alpha`, `error_px`, `visible`,
`ideal_action_in_range`, and `unclamped`. These are generated by the evaluation
command above; SFT and RL inputs must cover the same episode IDs.
